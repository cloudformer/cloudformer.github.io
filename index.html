Truly free when idle

Cloud services that cost nothing while nobody uses them.

AWS's "serverless" databases, caches and schedulers still bill every hour. IdleFree rebuilds them on Lambda, S3 and DynamoDB, behind the client you already use. You pay per request, and nothing when it's quiet.

Two kinds of project

Either an AWS service rebuilt behind its standard client, or an existing application moved onto Lambda with its code unchanged. In both cases the switch is one line, and so is the way back.

How every project works

Every project follows the same rules, so if you know one, you know them all.

≈ $0 when idle

Only pay-per-request primitives: S3, DynamoDB, SQS, Lambda, Step Functions, EventBridge. Nothing runs, polls or is provisioned while nobody uses it.

The client you already have

pymysql, redis-py, Airflow, redshift_connector, the vault CLI. Moving to the real service later is one import or one URL.

Only tested features count

Every feature runs on the real service and on the project, and the results are compared. The report is regenerated by every test run.

Refused, never silently different

What needs a real server raises NotSupportedError with the reason, and MIGRATION.md says when to move.

Your account, one command

Terraform from the first release, least-privilege IAM, arm64 and x86_64. Destroy removes everything.

Built for the long tail

MVPs, side projects, dev and staging: small, idle most of the time. Not a replacement for a busy production cluster.

Before a project starts: three checks

  1. AWS's own service bills while idle. If it scales to zero, or a lasting free tier covers small use, there is nothing to rebuild.
  2. No pay-per-use AWS service is a small switch away. If SQS or Athena already does the job, use it instead of imitating an old API on top of it.
  3. Never dress one AWS service up as another product. SQS stays SQS. A project rebuilds a service that bills while idle, behind the client its users already have.
